\section*{C. Modèle Pydantic de normalisation des tickets}
\addcontentsline{toc}{section}{C. Modèle Pydantic de normalisation}

Le modèle \texttt{NormalizedIssueModel} structure les données JSON brutes de Jira en un format unifié, réparti en quatre blocs : identité, temporalité, sémantique et acteurs.

\begin{lstlisting}[language=Python, caption={Modèle Pydantic de normalisation des tickets Jira}, label={lst:pydantic-model}]
from pydantic import BaseModel
from datetime import datetime
from typing import Optional, List

class NormalizedIssueModel(BaseModel):
    # Identity
    key: str
    url: str
    summary: str
    description: Optional[str]
    
    # Temporality
    created: datetime
    updated: datetime
    duedate: Optional[datetime]
    resolutiondate: Optional[datetime]
    
    # Semantics
    status: str
    status_category: str  # "To Do", "In Progress", "Done"
    issue_type: str       # "Bug", "Task", "Story", "Epic"
    priority: str
    
    # Actors
    assignee_id: Optional[str]
    assignee_name: Optional[str]
    assignee_avatar: Optional[str]
    reporter_id: Optional[str]
    
    # Relations & tracking
    issue_links: List[str]
    subtasks: List[str]
    sprint: Optional[str]
    story_points: Optional[int]
    
    # Time tracking
    time_original_estimate: Optional[int]
    time_estimate: Optional[int]
    time_spent: Optional[int]
\end{lstlisting}

\section*{E. Configuration Prometheus et règles d’alerte}
\addcontentsline{toc}{section}{E. Configuration Prometheus}

La stack de supervision est configurée via les fichiers suivants. Prometheus collecte les métriques exposées par le backend FastAPI et évalue les règles d’alerte personnalisées.

\begin{lstlisting}[
    language=yaml,
    breaklines=true,
    breakatwhitespace=true,
    basicstyle=\ttfamily\footnotesize,
    caption={Fichier de configuration Prometheus (\texttt{prometheus.yml})},
    label={lst:prometheus-config}
]
global:
  scrape_interval: 15s
  evaluation_interval: 30s

scrape_configs:
  - job_name: 'ai-platform'
    static_configs:
      - targets: ['backend:8000']
    metrics_path: '/metrics'
\end{lstlisting}

\begin{lstlisting}[
    language=yaml,
    breaklines=true,
    breakatwhitespace=true,
    basicstyle=\ttfamily\footnotesize,
    caption={Règles d’alerte Prometheus (\texttt{alert\_rules.yml})},
    label={lst:alert-rules}
]
groups:
  - name: project_health
    rules:
      - alert: CriticalWipRatio
        expr: project_wip_ratio > 0.6
        for: 5m
        annotations:
          summary: "WIP ratio critique pour le projet {{ $labels.project_key }}"
          severity: "CRITICAL"
      
      - alert: HighStaleRatio
        expr: stale_ratio > 0.2
        for: 10m
        annotations:
          summary: "Trop de tickets inactifs pour {{ $labels.project_key }}"
          severity: "WARNING"
      
      - alert: ProjectAtRisk
        expr: project_health_score == 2
        for: 5m
        annotations:
          summary: "Projet {{ $labels.project_key }} en état critique"
          severity: "CRITICAL"
\end{lstlisting}

\section*{F. Configuration du pipeline CI/CD Jenkins}
\addcontentsline{toc}{section}{F. Pipeline CI/CD Jenkins}

Le pipeline Jenkins automatise la construction, les tests et le déploiement de la plateforme sur les serveurs de NTT DATA à Tétouan.

\begin{lstlisting}[
    language=groovy,
    breaklines=true,
    breakatwhitespace=true,
    basicstyle=\ttfamily\scriptsize,
    caption={Jenkinsfile du pipeline CI/CD},
    label={lst:jenkinsfile}
]
pipeline {
    agent any
    
    environment {
        DOCKER_REGISTRY = "registry.nttdata.com"
        BACKEND_IMAGE = "${DOCKER_REGISTRY}/ai-platform-backend"
        FRONTEND_IMAGE = "${DOCKER_REGISTRY}/ai-platform-frontend"
    }
    
    stages {
        stage('Checkout') {
            steps {
                git branch: 'main',
                    url: 'https://umane.emeal.nttdata.com/git/FELTRIINTPROJ/nttdata-ai-agent-project-tracking'
            }
        }
        
        stage('Build Backend') {
            steps {
                sh 'docker build -t ${BACKEND_IMAGE}:${BUILD_ID} -f docker/backend/Dockerfile .'
            }
        }
        
        stage('Build Frontend') {
            steps {
                sh 'docker build -t ${FRONTEND_IMAGE}:${BUILD_ID} -f docker/frontend/Dockerfile .'
            }
        }
        
        stage('Run Tests') {
            steps {
                sh 'docker run --rm ${BACKEND_IMAGE}:${BUILD_ID} pytest tests/'
            }
        }
        
        stage('Push Images') {
            steps {
                sh 'docker push ${BACKEND_IMAGE}:${BUILD_ID}'
                sh 'docker push ${FRONTEND_IMAGE}:${BUILD_ID}'
            }
        }
        
        stage('Deploy to Production') {
            steps {
                sh 'ssh deploy@tetouan-server "docker-compose pull && docker-compose up -d"'
            }
        }
    }
    
    post {
        success {
            slackSend color: 'good', message: "[SUCCESS] Deploiement reussi (build ${BUILD_ID})"
        }
        failure {
            slackSend color: 'danger', message: "[FAILURE] Echec du deploiement (build ${BUILD_ID})"
        }
    }
}
\end{lstlisting}
